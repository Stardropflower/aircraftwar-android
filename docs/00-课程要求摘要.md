## 三、课件中与技术实现相关的要点

### 平台架构（第 8–14 页）
分层：Linux 内核 → 硬件抽象层（HAL）→ 原生 C/C++ 库 + Android Runtime(ART) → Java API Framework → 系统应用。
对**应用开发**而言，主要研究的是 **Java API Framework 层与应用层**。

### API 级别（第 6 页）
唯一标识平台版本与框架 API 状态；控制应用安装的兼容性范围（最低/目标 API 级别）；
运行时据 API 决定功能实现方式，避免调用不存在 API 而崩溃。

> 印证本项目的做法：`java.net.http`（Java 11 引入）在 Android 上缺失，必须替换 —— 这正是「按 API 决定实现方式」的现实案例。

### 应用开发基本流程（第 16 页）
设置工作区 → 编写应用 → 构建并运行 → 调试/剖析/测试 → 发布。

### 技术总览八个维度（第 17–29 页）

| 维度 | 关键点 |
|------|--------|
| 开发语言 / 环境 | Java 或 Kotlin；**Android Studio**（推荐，Panda 版）+ Gradle |
| UI | `View`（TextView/ImageView/Button…）、`ViewGroup`（LinearLayout / RelativeLayout / ConstraintLayout）、Activity / Fragment |
| 交互 | 按钮点击、手势滑动点击屏幕、系统 Home/Back 键 |
| 进程、线程 | Android 应用进程与 UI 线程模型 |
| 网络、数据 | 网络场景：账户登录校验、**游戏得分云同步、双人对战得分实时显示**、商品道具列表<br>存储场景：游戏模式设置持久化、单机排行榜、配置信息 |
| 架构模式 | MVC / MVP / **MVVM**；通过软件分层、接口隔离降低耦合 |
| 调试分析 | Android Studio 调试器（断点、变量窗格、求值监视）+ **Logcat** |
| 打包发布 | `Log.v/d/i/w/e` 日志级别；构建调试版 / 发布版 APK；DEX → zipalign → 签名 |

### 与我们项目的直接对应
