# AI 使用日志

> 课程实验二要求：填写 AI 使用日志，记录本次迁移中求助 AI 的内容。
> 课件第 27 页给出的推荐格式是：**原本想怎么做 / 采纳了什么 / 我改了什么**。
>
> 说明：这份日志记录的是真实使用情况。凡是 AI 给出的代码/建议，都经过本地编译、
> 单元测试或在模拟器上实际运行验证后才采纳；验证不通过的都已修正或弃用。

---

## 一、总体原则

| 用了 AI 做什么 | 没让 AI 做什么 |
|---|---|
| 查 Android 上某个 API 该怎么用（如 `SurfaceView` 生命周期、`SoundPool` 与 `MediaPlayer` 的取舍） | 不把整个 Windows 工程丢给 AI 让它「全自动改成安卓版」 |
| 解释报错原因、帮忙定位 Gradle/资源编译问题 | AI 给的代码没读懂就提交 |
| 生成机械性、模板化的代码（Getter、工厂类、布局脚手架），再由自己审阅修改 | 让 AI 代替自己决定游戏规则与数值平衡 |
| 帮忙整理文档（README、迁移分析、本日志）的表述 | 让 AI 代替自己做技术选型判断而不复核 |

**每条建议都做了的验证**：`assembleDebug` 编译 → `testDebugUnitTest` 跑 22 项单元测试 →
在 Android 15 模拟器上实际运行并截图检查。

## 二、按阶段记录

### 阶段 1：搭建 Android 工程与工具链

| 项 | 内容 |
|---|---|
| **原本想怎么做** | 装了 Android Studio 就想直接建工程开写，没意识到 SDK 版本和 JDK 版本有匹配关系 |
| **求助内容** | 「AGP 对 JDK 版本的要求是什么」「本机是 JDK 25，AGP 8.x 能用吗」 |
| **采纳** | 得知 AGP 8.x 官方支持上限是 JDK 21，改用 Android Studio 自带的 JBR 21 作为构建 JDK，不动本机的 JDK 25 |
| **我改了/做了什么** | 在命令行构建时显式设 `JAVA_HOME` 指向 `android-studio\jbr`；并把这条写进了 `docs/04-构建环境说明.md`，避免以后换机器再踩 |

| 项 | 内容 |
|---|---|
| **原本想怎么做** | 项目放在 `L:\claudecode\雷霆战机劣质版\` 下（中文目录），觉得 Windows 路径支持中文没问题 |
| **求助内容** | 「AGP 报 `Your project path contains non-ASCII characters` 怎么解决」 |
| **采纳** | AI 提到可以加 `android.overridePathCheck=true` 绕过 |
| **我验证后发现不够** | 加上之后**能编译出 APK**，但单元测试抛 `ClassNotFoundException`（class 文件明明存在）。把同一套代码复制到 `L:\aw-ascii-probe` 测试立刻全绿 —— 说明那个开关只放行了构建检查，把「构建报错」变成了「运行时莫名失败」 |
| **最终做法** | 没有停在「绕过」，而是把仓库整个迁到 `L:\android-projects\AircraftWar-Android`，并移除 override。结论写进了 `docs/04-构建环境说明.md` 第一节 |

> 这条是本日志里最重要的一次「没有全盘采纳建议」：AI 给的是能过编译的权宜之计，
> 实测发现问题没解决，最后改成了根本解法。

### 阶段 2：盘点 Windows 代码、确定迁移边界

| 项 | 内容 |
|---|---|
| **原本想怎么做** | 凭印象判断「哪些类能直接搬」。结果发现凭印象不可靠——`AbstractFlyingObject` 里藏着 `BufferedImage` 字段，看着像纯逻辑其实不是 |
| **求助内容** | 「怎么系统地判断一个 Java 文件有没有平台依赖」 |
| **采纳** | 改成按 `import` 扫描：凡依赖 Android 上不存在的 API 就算需适配 |
| **我做了什么** | 自己写脚本逐文件扫描 `import`，得出 60 个文件中 37 个纯 Java、9 个换类型、1 个保留内核、13 个必须重写。这组数字写进了迁移分析和任务书 |

### 阶段 3：核心逻辑层迁移（实验二主体）

| 项 | 内容 |
|---|---|
| **原本想怎么做** | 把 `Game`（继承 `JPanel`）整个类搬到安卓，再把 `paintComponent` 换掉 |
| **求助内容** | 「这个类既管游戏规则又管画图，怎么拆比较干净」 |
| **采纳** | 拆成 `GameWorld`（纯逻辑，不含任何 Android API）+ `GameRenderer`（只负责画） |
| **我做了什么** | 亲手把 `Game` 里的 14 步主循环、碰撞三趟判定、掉落、背包、难度递增逐段搬出来；**去掉了 `SwingUtilities`、`Timer`、`paint`、音效、DAO**。搬完立刻写单元测试验证行为没变 |

| 项 | 内容 |
|---|---|
| **原本想怎么做** | 英雄机沿用 Windows 版的单例写法，省事 |
| **求助内容** | 「双人模式需要两架飞机，单例怎么处理」 |
| **采纳** | 改成可实例化 + `playerSlot` 区分玩家 |
| **我做了什么** | 改了 `HeroAircraft` 的构造与 `reset`，并同步修改所有调用点；为了保证不破坏原行为，补了「双人两架独立飞机」等测试 |

| 项 | 内容 |
|---|---|
| **原本想怎么做** | 火力加速照搬 Windows 版的「后台线程 sleep + `SwingUtilities.invokeLater`」 |
| **求助内容** | 「安卓上没有 `SwingUtilities`，这个定时回调怎么改」 |
| **采纳** | 建议改成按逻辑帧倒计时 |
| **我做了什么** | 改成 `BOOST_DURATION_FRAMES = 150`（150 帧 × 40ms = 6 秒），去掉线程。好处是确定、可单测；顺带发现原版加速结束后 `isSpreadMode` 没复位导致按 Q 首次无效，一并修了 |

### 阶段 4：渲染层与主循环（SurfaceView）

| 项 | 内容 |
|---|---|
| **原本想怎么做** | 用普通 `View` + `invalidate()` 驱动画面 |
| **求助内容** | 「2D 游戏画面为什么推荐 SurfaceView 而不是普通 View」 |
| **采纳** | 用 `SurfaceView` + 独立渲染线程 |
| **我做了什么** | 参照课程示例 `SurfaceViewDemo` 的骨架（`implements SurfaceHolder.Callback, Runnable`），自己实现了：逻辑固定 25Hz、渲染尽量 60fps、中间用插值补顺；`surfaceDestroyed` 里停线程并 join |

| 项 | 内容 |
|---|---|
| **原本想怎么做** | 触屏事件里直接改英雄机坐标 |
| **求助内容** | 「渲染线程在遍历实体列表，主线程改坐标会不会有问题」 |
| **采纳** | 建议只在主线程写 volatile 变量，由渲染线程在每个逻辑步消费 |
| **我做了什么** | 改成「主线程只投递目标坐标 → 渲染线程 `applyInput()` 统一应用」。后来做背包点击时继续沿用这个模式（见阶段 5） |

### 阶段 5：音效、背包点击使用、皮肤系统

| 项 | 内容 |
|---|---|
| **原本想怎么做** | 背包点击直接在 `onTouchEvent` 里调 `world.useBackpackItem()` |
| **求助内容** | 「这样做会不会有并发问题」 |
| **采纳** | 会——背包是核心层列表，渲染线程正在遍历它，一边遍历一边改会抛 `ConcurrentModificationException` |
| **我做了什么** | 改成主线程只置 `volatile boolean pendingBackpackUse`，渲染线程在逻辑步里消费。实测点击后可正常使用且不崩 |

| 项 | 内容 |
|---|---|
| **原本想怎么做** | 短音效用 `MediaPlayer` 一个个放 |
| **求助内容** | 「游戏里几百次短音效，用 MediaPlayer 还是 SoundPool」 |
| **采纳** | 短音效 `SoundPool`、BGM `MediaPlayer` |
| **我做了什么** | 自己实现 `SoundManager`，处理了：SoundPool 预加载、BGM 切曲不重复重启、切后台暂停、退出释放。**并给 BGM 相关方法加了 synchronized**，因为渲染线程（Boss 换曲）和主线程（生命周期）会并发调用 |

### 阶段 6：对照实验二要求做合规修正

| 项 | 内容 |
|---|---|
| **原本想怎么做** | 图片放 `assets/`，用 `BitmapFactory.decodeStream` |
| **对照实验二要求发现** | 课件明确要求「图片资源全部走 **res/drawable + BitmapFactory.decodeResource**」 |
| **求助内容** | 「图片放 res/drawable 后，高密度屏上会不会被自动放大」 |
| **采纳** | 会——不带密度限定符的 drawable 会被当作 mdpi 并放大，而本项目用图片宽高做碰撞判定 |
| **我做了什么** | 改成放 `res/drawable-nodpi`（禁止密度缩放），解码时再设 `inScaled = false` 做双保险；顺带发现 `elitePlus.png`、`elitePro.png`、`prop_bulletPlus.png` 三个文件名含大写，**res 目录不允许**，全部改成小写 |

## 三、AI 给过但我没采纳/改了的地方（汇总）

| AI 建议 | 为什么不直接用 | 最后怎么做的 |
|---|---|---|
| `android.overridePathCheck=true` 绕过中文路径 | 实测只能过编译，单元测试仍崩 | 把仓库迁到纯 ASCII 路径 |
| 火力加速继续用后台线程 | 安卓没有 `SwingUtilities`，且多线程改状态有竞态 | 改成按帧倒计时 |
| 背包点击直接调 `useBackpackItem` | 会跨线程改核心层列表 | 改成投递标记、渲染线程消费 |
| 图片放 `res/drawable` 即可 | 会被按密度放大，碰撞框全错 | 放 `drawable-nodpi` + `inScaled=false` |
| `minSdk` 用 24 兼容更多机型 | 课程要求最小 API 级别在 33~35 之间 | 按课程要求改为 33 |

## 四、验证方式（每条采纳的建议都过了这一关）

```powershell
# 1. 编译
& "L:\android-toolchain\gradle-8.11.1\bin\gradle.bat" assembleDebug

# 2. 单元测试（22 项，纯 JVM，不需要手机）
& "L:\android-toolchain\gradle-8.11.1\bin\gradle.bat" testDebugUnitTest --rerun-tasks

# 3. 模拟器实跑 + 截图 + 看日志
& "L:\android-sdk\platform-tools\adb.exe" install -r app\build\outputs\apk\debug\app-debug.apk
& "L:\android-sdk\platform-tools\adb.exe" logcat -d -s AndroidRuntime:E
```

只有三步都通过的改动才会提交。
