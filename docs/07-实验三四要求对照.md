## 五、需要你决策的 6 件事

> 下面每条都给了「建议」和「改动成本」，你只需要回复编号 + 改/不改。

### ① 音乐开关的界面（实验三第 3 项，**明确未完成**）

- **现状**：开关的代码能力有，但没有按钮，玩家无法操作
- **建议**：**必须改**。这是实验三写的「实验内容」，缺了说不过去
- **成本**：小。在主菜单和游戏内 HUD 各加一个图标按钮，接上已有的 `setMuted`
- **有两种做法**：
  - A. 主菜单加一个「音效：开/关」按钮（简单，1 处）
  - B. 主菜单 + 游戏内 HUD 都加（体验更好，2 处）

### ② 音频资源从 `assets/videos` 迁到 `res/raw`（实验三第 18 页，**明确写了**）

- **现状**：`assets/videos/*.wav` + `AssetManager.openFd()`
- **建议**：**建议改**。课件第 18 页原文「Android 的音频文件存放在应用项目的 res/raw 目录下」，第 20 页示例是 `soundPool.load(context, R.raw.click, 1)`，第 22 页第一步就是「将音乐资源放到 res/raw 文件夹下」。这是老师会看的点
- **成本**：小。移文件 + 改 `SoundManager` 里 4 个音效的 load 方式和 2 首 BGM 的 setDataSource
- **风险**：低，改完在模拟器上验证一遍即可

### ③ `music` 包 + `MyMediaPlayer` / `MySoundPool` 两个类（实验三第 22–23 页）

- **现状**：`audio/SoundManager` 一个类兼顾两者
- **建议**：**可以改，也可以不改**。功能完全等价，只是命名与文件组织不同
- **成本**：中。要拆类、改调用点
- **我的看法**：如果老师明确按课件目录检查，改更保险；但如果只看功能，现在这样更内聚（一个类管完整音频生命周期，不存在两个类都要 release 的时序问题）。**这个我可以现场用「为什么合并成一个类」解释**

### ④ 显式 `Handler` 类替代 `runOnUiThread`（实验三第 28–32 页）

- **现状**：`runOnUiThread`（内部就是主线程 Handler 的 `post`）
- **建议**：**建议改**。课件给了 `class Mhandler extends Handler` + `handleMessage` + `msg.what` 的完整示例，而且第 30 页专门出了思考题「游戏结束时如何跳转到排行榜页面」。用显式 Handler 更贴课件
- **成本**：小。`GameActivity` 里加一个 Handler 子类，把 `runOnUiThread` 换成 `sendEmptyMessage`
- **注意**：改完**行为不变**，只是写法更贴课件

### ⑤ XML 布局（实验三第 7–9 页）

- **现状**：全 Java 动态布局，`res/layout` 为空
- **建议**：**建议至少把主菜单改成 XML**。课件两种都讲了，但 XML 是更标准的做法，也更容易讲「`setContentView(R.layout.activity_main)`」这条链路
- **成本**：中。只改 `MainActivity` 一个页面比较划算，皮肤页和游戏页保持动态布局
- **权衡**：如果时间紧，可以不改，讲清「我们用了动态布局这条路线，因为难度按钮数量随难度枚举变化」

### ⑥ 实验四整体（**必须做**）

- **现状**：4 项全未做
- **建议**：**必须做**。中期检查在实验四之后，且实验四验收标准就是这 4 项
- **成本**：中大。需要：排行榜实体类 + `SQLiteOpenHelper` + DAO + `ListView` + `BaseAdapter` + 排行榜页面 + 删除按钮 + 第一名高亮 + 游戏结束时写入数据库 + Handler 跳转

## 七、附：实验三「音效播放时机」对照（课件第 23 页）

课件点名了 4 个音效及触发时机，我们的实现：

| 音效 | 课件说的触发时机 | 我们的实现 | 一致性 |
|---|---|---|---|
| `bullet_hit.wav` | 敌机子弹击中英雄机，或英雄机子弹击中敌机 | 英雄机子弹打死敌机时播（`onEnemyKilled`）；敌机子弹击中英雄机时**没有单独播** | ⚠️ 少了「敌方击中我方」那一半 |
| `bomb_explosion.wav` | 英雄机和炸弹道具碰撞（课件标注「可选」） | 炸弹生效时播（`onBombDetonated`） | ✅ |
| `get_supply.wav` | 英雄机和非炸弹道具碰撞 | 拾取道具时播（`onItemPicked`） | ✅ |
| `game_over.wav` | 游戏结束时 | 游戏结束时播（`onGameOver`），用的是较短那版 `game_over_ori.wav` | 🟡 文件名与课件不同 |

> 关于 `game_over_ori.wav`：项目里有两版结束音，`game_over.wav` 有 1.16 MB，
> SoundPool 解码后会占好几 MB 内存；`game_over_ori.wav` 只有 90 KB。
> 这个取舍可以在答辩时讲（是个能体现工程判断的点）。
> 但如果老师对照文件名检查，改成 `game_over.wav` 更保险——**要不要改你定**。
