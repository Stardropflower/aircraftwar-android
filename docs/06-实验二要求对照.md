## 四、五个必踩的坑 —— 我们的处理（课件第 24 页）

| 坑 | 课件给的现象 | 我们是否踩到 | 处理 |
|---|------|------|------|
| **资源命名不合法** | R 不生成，`Cannot resolve symbol R` | **踩到了** | `elitePlus.png`、`elitePro.png`、`prop_bulletPlus.png` 三个文件名含大写，迁到 res 时全部改小写（`eliteplus` / `elitepro` / `prop_bulletplus`） |
| **图片反复加载** | 内存暴涨、卡顿、OOM | 避开了 | `Assets.load()` 在进入页时一次性解码并缓存到 Map，循环里只 `drawBitmap`，不重复 decode |
| **坐标写死像素** | 换机器就跑出屏幕 | 避开了 | 逻辑坐标固定宽 512，绘制时 `canvas.scale(viewWidth/512)`；战场高度按屏幕长宽比算 |
| **绘制线程没停** | 退出后日志刷屏、再进黑屏 | 避开了 | `surfaceDestroyed()` 置 `running=false` 并 `join(1000)` 等线程真正结束 |
| **持有 Activity 引用** | 内存泄漏、Activity 无法回收 | 避开了 | `Assets` / `SoundManager` 都用 `context.getApplicationContext()` |

## 六、工程目录结构说明（课件第 7–13 页对应）

```
AircraftWar2026/
├── app/
│   ├── manifests/AndroidManifest.xml   # 三个 Activity 声明、图标、主题
│   ├── java/edu/hitsz/aircraftwar/
│   │   ├── core/       # 游戏规则（43 个类，纯 Java，无 android import）
│   │   ├── render/     # SurfaceView 渲染、主循环、图片资源
│   │   ├── audio/      # SoundPool / MediaPlayer
│   │   ├── data/       # SharedPreferences 存档
│   │   ├── net/        # ← 网络对战（待新增，孙琳凯）
│   │   └── ui/         # Activity
│   ├── res/
│   │   ├── drawable-nodpi/   # 22 张游戏图片（全小写，禁止密度缩放）
│   │   ├── drawable/         # 启动图标（vector）
│   │   └── values/           # strings / colors / themes
│   └── build.gradle          # minSdk 33 / targetSdk 35 / Java 17
├── assets/videos/            # 音频（7 个 wav）
├── docs/                     # 实验文档
├── guide/                    # 验收与上手文档
├── build.gradle              # 顶层，只声明 AGP 版本
├── settings.gradle           # rootProject.name = AircraftWar2026
├── gradle.properties
└── local.properties          # sdk.dir（不入库）
```

> 关于图片目录为什么是 `drawable-nodpi` 而不是 `drawable`：
> 不带密度限定符的 `drawable` 会被系统按屏幕密度缩放（420dpi 屏会放大 2.6 倍）。
> 本项目用图片宽高做碰撞判定，被放大后碰撞框会全错，所以必须用 `nodpi`
> 并在解码时设 `inScaled = false`。
