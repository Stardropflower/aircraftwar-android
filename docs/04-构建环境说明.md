# 构建环境说明

> 记录本机已配置好的 Android 工具链位置与版本，以及构建时踩到的坑。

## 〇、⚠️ 项目必须放在纯 ASCII 路径下

本项目仓库位置：**`L:\android-projects\AircraftWar-Android`**

最初它放在 `L:\claudecode\雷霆战机劣质版\AircraftWar-Android`（中文目录），结果：

| 阶段 | 中文路径下的结果 |
|------|------------------|
| AGP 配置 | ❌ 直接拒绝构建：`Your project path contains non-ASCII characters` |
| 加上 `android.overridePathCheck=true` 后，编译 | ✅ 可以编译、可以产出 APK |
| **单元测试** | ❌ `ClassNotFoundException: ...CoreLogicTest` —— 测试类明明编译出来了，但 JUnit 运行器加载不到 |

**同一套代码复制到 `L:\aw-ascii-probe`（纯 ASCII）后，测试立刻全绿。**
说明那个 override 只放行了 AGP 的路径检查，**并不能真正修复非 ASCII 路径带来的问题**，
它把「构建时报错」变成了「运行时莫名失败」，反而更难查。

因此：**仓库已迁到 `L:\android-projects\AircraftWar-Android`**，
并移除了 `android.overridePathCheck`。以后如果有人把项目放回中文路径，
AGP 会明确报错——这是好事，比测试静默失败强。

## 二、命令行构建

```powershell
$env:JAVA_HOME    = "L:\android-toolchain\android-studio\jbr"
$env:ANDROID_HOME = "L:\android-sdk"
cd L:\android-projects\AircraftWar-Android

# 构建调试包
& "L:\android-toolchain\gradle-8.11.1\bin\gradle.bat" assembleDebug --console=plain

# 跑纯逻辑层单元测试（core/ 不含 Android API，在 JVM 上直接跑）
& "L:\android-toolchain\gradle-8.11.1\bin\gradle.bat" testDebugUnitTest --console=plain
```

产物：`app/build/outputs/apk/debug/app-debug.apk`

## 三、关于路径（已解决，见第〇节）

## 四、用 Android Studio 打开

1. 启动 `L:\android-toolchain\android-studio\bin\studio64.exe`
2. 首次启动会提示导入设置，选 **Do not import settings**
3. 在欢迎页 **Open** → 选择 `L:\android-projects\AircraftWar-Android`
   （**选这个目录本身，不要选里面的 app 目录**）
4. 首次同步会自动识别 SDK 位置（也可在 SDK Manager 里手动指向 `L:\android-sdk`）
5. 等待 Gradle Sync 完成，即可用 Run 按钮部署

> `local.properties`（记录 `sdk.dir`）已生成且被 `.gitignore` 排除，不会入库。
