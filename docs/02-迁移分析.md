# 原有功能迁移分析

> 这是任务书第 2 项的核心内容：**哪些代码能复用、哪些要重写、为什么**。
> 分析对象：Windows 版 `aircraftwar`（Java Swing，仓库 `Stardropflower/aircraftwar`）。

## 0. 判定方法

不靠印象，按「是否 `import` 了 Android 上不存在的 API」逐文件判定：

| 平台专属 API | Android 上的情况 |
|---|---|
| `javax.swing.*` / `java.awt.*`（除少数几何类） | ❌ 完全没有（Android 用 `android.view` / `android.widget` / `android.graphics`） |
| `javax.sound.sampled.*` | ❌ 没有（用 `SoundPool` / `MediaPlayer`） |
| `javax.imageio.ImageIO` | ❌ 没有（用 `BitmapFactory`） |
| `java.net.http.*` | ⚠️ 预期没有（Java 11 才引入，见 §6 验证项） |
| `java.io.ObjectOutputStream`（Java 序列化） | ⚠️ 能用但不推荐（版本兼容差，Android 建议 JSON） |
| `java.nio.file.*` | ✅ API 26+ 可用（[Android 文档](https://developer.android.com/reference/java/nio/file/package-summary)：Added in API level 26） |
| 纯 Java（集合、数学、字符串） | ✅ 完全可用 |

## 1. 总体结论

对 60 个源文件（不含 JUnit 测试类）逐个扫描后：

| 级别 | 含义 | 文件数 | 占比 |
|------|------|--------|------|
| **A** | 原样复用（无任何平台 API） | **37** | 62% |
| **B** | 机械替换即可复用 | **9** | 15% |
| **C** | 保留内核逻辑、重写平台外壳 | **1** | 2% |
| **D** | 必须完全重写 | **13** | 22% |

**结论：游戏内核（对象模型 + 规则 + 状态机）约 77%（A+B+C）可以迁移，需要重写的是
渲染、输入、音效、界面、网络传输这五个「平台边界」。** 这正是本次迁移的核心价值：
工作量集中在适配层，而不是把游戏重做一遍。

## 2. A 级：原样复用（37 个文件）

这些文件只依赖 JDK 集合与基础类型，**改包名后可直接编译**：

| 包 | 文件 | 复用理由 |
|----|------|----------|
| `bullet/` | `BaseBullet`、`HeroBullet`、`EnemyBullet` | 只做坐标推进与越界判定，与 UI 无关 |
| `strategy/` | `ShootStrategy`、`StraightShootStrategy`、`SpreadShootStrategy`、`RoundShootStrategy`、`EliteProShootStrategy`、`ShootContext` | 策略模式产出子弹对象，不涉及绘制 |
| `aircraft/` | `AbstractAircraft`、`AbstractEnemy`、`MobEnemy`、`EliteEnemy`、`ElitePlusEnemy`、`EliteProEnemy`、`BossEnemy` | 血量、冻结/减速、掉落概率、弹幕节奏等规则纯计算 |
| `aircraft/Factory/` | `EnemyFactory` + 4 个具体工厂 | 工厂模式，纯对象创建 |
| `item/` | `AbstractItem`、`ItemFactory`、`BombSubject`、`FreezeSubject`、`GameEventSubject`、`GameEventObserver` | 观察者模式与道具生成，纯 Java |
| `dao/` | `RankDAO`、`ScoreRecord`、`Difficulty`、`RankDataAccessException`、`RankDAOFactory`、`FallbackRankDAO` | 接口、模型与「云端优先+本地兜底」的编排逻辑 |
| `application/` | `EasyGame`、`NormalGame`、`HardGame` | 三套难度参数与递增公式，是调好的数值，直接继承 |

> 特别值得保留的：`Game` 里的这些规则**一行都不用改**就能沿用 ——
> 刷怪节奏、Boss 分数阈值（简单无 Boss / 普通 1000 / 困难 800）、困难模式 Elo 射速、
> 冻结 150 帧、背包容量 2、炸弹对 Boss 与 ElitePro 各 100 伤害、子弹命中即消耗、
> 一颗子弹不穿透、皮肤解锁只读本地最高分。

## 3. B 级：机械替换（9 个文件）

| 文件 | 唯一平台依赖 | 改法 |
|------|--------------|------|
| `basic/AbstractFlyingObject` | `java.awt.image.BufferedImage` | 字段与 `getImage()` 返回类型改为 `android.graphics.Bitmap`；**坐标/碰撞/插值数学全部保留** |
| `item/Item`、`AbstractItem`※、`BloodItem`、`BombItem`、`FireItem`、`FreezeItem`、`SuperFireItem` | `BufferedImage` | 同上（`Item` 接口的 `getImage()` 签名） |
| `aircraft/HeroAircraft` | `BufferedImage` + `javax.swing.SwingUtilities.invokeLater` | 图像改 `Bitmap`；`invokeLater` 改为 `Handler(Looper.getMainLooper()).post(...)`（火力加速超时回调） |
| `dao/SupabaseConfig` | `java.nio.file` 读 jar 同级配置 | Android 没有「jar 同级目录」概念：改从 `assets/`、`SharedPreferences` 或 `BuildConfig` 注入 |

> 这类文件「逻辑不动、类型换掉」，是迁移中最省事的一档。
> ※ `AbstractItem` 本身无平台 API，但它实现 `Item`，接口签名一改它要跟着改。

## 4. C 级：保留内核、重写外壳（1 个文件）

### `application/Game` —— 项目最核心也最需要小心的一个类

它同时装了两样东西，必须拆开看：

**要保留的（游戏内核）**
- 五个实体列表与它们之间的处理顺序
- `tick()` 的推进顺序：冻结倒计时 → Boss 生成 → 刷怪 → 射击 → 移动 → 碰撞 → 清理 → 背景滚动 → 死亡判定 → 难度递增
- 碰撞判定三趟：敌弹 vs 英雄机、英雄弹 vs 敌机（命中即消耗）、英雄机 vs 敌机（**独立于子弹列表**）
- 炸弹/冰冻的 `onBombDetonated()` / `onFreezeActivated()`
- 背包的 `Stack` 语义与「空格消耗栈顶」
- **逻辑 25Hz + 渲染 60fps 插值**的架构（`snapshotPosition` / `renderX(alpha)` 这套已经跑通）
- 结算口径：只有超过本机最高分才提交

**要替换的（平台外壳）**

| 原实现 | 问题 | Android 方案 |
|--------|------|--------------|
| `extends JPanel` + `paintComponent(Graphics)` | 无 Swing | 逻辑层抽成不依赖 UI 的 `GameWorld`，渲染交给 `SurfaceView` 的 `Canvas` |
| `javax.swing.Timer` 回调在 EDT | 无 EDT | 独立渲染线程（`SurfaceHolder.lockCanvas`）+ `Choreographer` 对齐 vsync；时间累加器沿用 |
| `g.drawImage(BufferedImage…)` | 无 AWT Graphics | `Canvas.drawBitmap` |
| `Graphics2D` 自绘 HUD（圆角卡、渐变血条、字形轮廓标题） | 无 AWT | `Canvas.drawRoundRect` + `LinearGradient` + `Paint`；标题的渐变/描边可用 `Shader` + `drawText` 实现 |
| `JOptionPane` 输入昵称 | 无 Swing | `AlertDialog` + `EditText` |
| `RankingDialog` / `SkinDialog` / `StartMenu` / `ChoiceDialog` / `GuideDialog` | 无 Swing | `Activity` + XML 布局（或 `RecyclerView` 做榜单） |

> 建议做法：把 `Game` 拆成 `GameWorld`（纯逻辑，可单元测试）+ `GameRenderer`（平台相关）。
> 拆完之后 Windows 版和 Android 版可以**共用同一个 `GameWorld`**，这也顺带证明了「可复用」不是嘴上说说。

## 5. D 级：完全重写（13 个文件）

| 文件 | 为什么不能复用 | Android 替代 |
|------|----------------|--------------|
| `application/Main` | 入口是 `main()` + `SwingUtilities` | `Activity.onCreate` + `AndroidManifest` |
| `application/StartMenu` | `JFrame` + 自绘背景/字形轮廓标题 + `RadialGradientPaint` | `MenuActivity` + 布局；背景用 `ImageView` 或自定义 View |
| `application/MenuButton` | 继承 `JComponent`、用 `MouseAdapter` 与 `javax.swing.Timer` 做悬停缓动 | 自定义 `View` + `onTouchEvent` + `ValueAnimator`；或标准 `MaterialButton` |
| `application/UiTheme` | `UIManager` / FlatLaf 是 Swing 专属 | `themes.xml` + `colors.xml` + `styles.xml`；圆角/阴影用 `shape` drawable |
| `application/ChoiceDialog`、`GuideDialog` | `JDialog` + `BoxLayout` + `JScrollPane` | `Dialog`/`AlertDialog` + 布局；指南用 `ScrollView` |
| `application/RankingDialog` | `JTable` + `AbstractTableModel` | `RecyclerView` + `Adapter`（分页/下拉刷新都好做） |
| `application/SkinDialog` | `JDialog` + `JLabel` 预览 + 解锁判定 | `Dialog` + `RecyclerView`/`ViewPager2`；**解锁判定逻辑可原样搬**（读本地最高分） |
| `application/HeroController` | `MouseAdapter` / `KeyAdapter` | `onTouchEvent`（`ACTION_MOVE` 跟随手指）；暂停/切弹道改界面按钮 |
| `application/ImageManager` | `ImageIO.read` + 静态 `Map<className, BufferedImage>` | `BitmapFactory.decodeStream(assets)`；**「类名→图片」的映射结构可保留** |
| `application/SoundManager` | `javax.sound.sampled.Clip` | `SoundPool`（短音效，需预加载 + 音效池） |
| `application/MusicThread` | `Clip.loop` + 自建线程轮询 | `MediaPlayer`（`setLooping(true)`）+ 生命周期回调 |
| `dao/SupabaseRankDAO` | `java.net.http.HttpClient` | **OkHttp / Retrofit**（或退一步 `HttpURLConnection`）；PostgREST 的 URL 拼装与 JSON 解析逻辑可保留 |

## 6. 关键风险与验证清单

迁移第一步就应先验证这几条，避免架构定完后才发现走不通：

| # | 待验证 | 为什么重要 | 验证方法 |
|---|--------|-----------|----------|
| R1 | `java.net.http` 在 Android 上是否可用 | 若可用则 `SupabaseRankDAO` 能省一大截；若不可用必须换 OkHttp | 新建一个空类 `import java.net.http.HttpClient;`，编译看是否报错 |
| R2 | `minSdk` 定多少 | 现有 `SupabaseConfig` 用 `java.nio.file`（需 API 26+）；若 `minSdk < 26` 就得改读配置方式 | 按目标机型定 `minSdk`，再决定是否保留 `java.nio.file` |
| R3 | 游戏循环帧率稳定性 | Android 设备差异大，25Hz 逻辑 + 60fps 插值必须实测不抖 | 在真机上打印帧间隔分布，观察 `Choreographer` 掉帧 |
| R4 | 触摸跟手性 | 鼠标能瞬时定位，手指拖动有偏移；飞机若被手指遮住体验很差 | 英雄机位置相对手指上移一个固定偏移，实测手感 |
| R5 | 音频延迟 | `SoundPool` 加载时机不当会导致「开枪没声音」 | 页面 `onCreate` 预加载，避免每帧 `load` |
| R6 | 后台/来电时暂停 | Android 会随时打断应用 | `onPause` 暂停游戏与音乐，`onResume` 恢复（对应已有的暂停功能） |

## 7. 迁移实施顺序

对应课程实验二~五，每一步都留下可运行的 APK，而不是最后一次性集成：

| 步骤 | 对应实验 | 内容 | 完成标志 |
|------|----------|------|----------|
| M1 | 二 | 建工程、搬 A 级文件、拆 `Game` 为 `GameWorld` | 纯逻辑层能在 JVM 上跑单元测试（不开 Android） |
| M2 | 二 | `SurfaceView` 渲染 + 触屏输入 + 主循环 | 真机上飞机能跟着手指飞、能自动射击 |
| M3 | 三 | HUD、菜单、暂停、音效 BGM、皮肤页 | 玩法闭合，除排行榜外与 Windows 版一致 |
| M4 | 四 | 排行榜（本地 + 云端）、难度/模式持久化 | 成绩能存能读，断网不崩 |
| M5 | 五 | 网络对战（见任务书第 3 项）、断线重连 | 两台设备能同房对战 |
| M6 | 六 | 扩展功能（幽灵竞速等） | 加分项 |
| M7 | 七 | 结题报告、演示、打包签名 | 提交 |

> 每一步都验证过再走下一步 —— 这也是 Windows 版这两个学期一路踩坑换来的经验：
> 一次性写一大堆再联调，出问题时根本分不清是哪层坏了。
