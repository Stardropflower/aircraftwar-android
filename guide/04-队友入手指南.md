把同一套代码复制到纯英文路径，测试立刻全绿。

所以请放在类似 `D:\work\AircraftWar2026` 这样的路径下，**不要放在「桌面」「新建文件夹」这类中文路径**。

### 其他课程硬性要求（别改坏了）

- 项目名必须叫 **AircraftWar2026**（已配好，在 `settings.gradle`）
- **minSdk 必须是 33~35 之间**（已配成 33，即 Android 13）
- 图片必须在 **`res/drawable-nodpi`**，用 `BitmapFactory.decodeResource`

## 六、你的任务：网络对战怎么做

### 6.1 任务书里已经定好的设计（照着做就行）

> **比分竞赛，不是实时互射。**
> 两名玩家凭房间码进入同一局，各自在本地运行关卡，实时看到对方分数与血量，
> 先达到目标分者获胜，胜负由服务端判定。

**为什么不做实时互射**：那需要同步子弹、碰撞、血量（状态同步），对延迟极敏感；
只同步一个分数的话，延迟 200ms 都基本无感，实现复杂度低一个数量级。

**协议草案**（JSON over WebSocket）：

```jsonc
// 客户端 → 服务端
{"type":"create", "name":"玩家A", "difficulty":"NORMAL", "target":5000}
{"type":"join",   "room":"A3F9K2", "name":"玩家B"}
{"type":"score",  "room":"A3F9K2", "score":1200, "hp":900}   // 每 1 秒上报一次
{"type":"leave",  "room":"A3F9K2"}

// 服务端 → 客户端
{"type":"joined", "room":"A3F9K2", "you":"A", "opponent":"玩家B"}
{"type":"state",  "a":{"name":"玩家A","score":1200,"hp":900},
                  "b":{"name":"玩家B","score":950,"hp":1000}}
{"type":"over",   "winner":"A", "scoreA":5000, "scoreB":4210}
{"type":"opponent_left"}
```

**关键约定**：
- 房间码 6 位（大写字母+数字，排除 O/0/I/1 这种容易看错的）
- **服务端权威**判定胜负，客户端不自己判（防作弊）
- 断线后服务端保留房间 60 秒，重连补发当前 `state`
- 心跳：客户端每 15s 发 ping，2 次没响应判掉线

### 6.2 接入现有代码的三个点

**① 拿分数**（在 `GameActivity` 里）

```java
GameWorld world = ...;          // 已经创建好了
int score = world.totalScore(); // 队伍总分（单人模式就是个人分）
int hp = world.getHero(0).getHp();
```

**② 定时上报**（不要用渲染线程做网络 IO！）

渲染线程每 40ms 跑一次游戏逻辑，在里面做网络请求会卡死画面。正确做法是**用主线程的 Handler 定时上报**：

```java
Handler handler = new Handler(Looper.getMainLooper());
Runnable reporter = new Runnable() {
    @Override public void run() {
        session.reportScore(world.totalScore(), world.getHero(0).getHp());
        handler.postDelayed(this, 1000);   // 每 1 秒一次
    }
};
handler.post(reporter);
// onDestroy 里记得 handler.removeCallbacks(reporter)
```

**③ 把对手信息显示出来**

在 `GameRenderer` 里加一个方法（不动核心层）：

```java
// GameRenderer 里
private String opponentText = null;
public void setOpponentInfo(String text) { this.opponentText = text; }
// 然后在 drawHud() 里画出来
```

然后在 `GameSurfaceView` 里加个转发方法，或者让 `GameActivity` 直接持有 renderer 引用。

> ⚠️ 注意：`GameRenderer` 被渲染线程使用，你在主线程设值时要保证是简单赋值（`volatile` 字段），
> 不要在主线程直接改 Renderer 内部正在用的集合。

### 6.3 建议的代码组织

新建一个 `net/` 包，别往现有包里塞：

```
app/src/main/java/edu/hitsz/aircraftwar/net/
├── BattleProtocol.java    // 消息类型与 JSON 编解码
├── BattleSession.java     // 一个对战会话：连接、心跳、重连、状态
├── BattleClient.java      // WebSocket 连接封装（OkHttp）
└── BattleRoomActivity.java // 房间创建/加入的界面
```

依赖：在 `app/build.gradle` 加

```gradle
implementation 'com.squareup.okhttp3:okhttp:4.12.0'
implementation 'com.google.code.gson:gson:2.11.0'
```

（Gson 在 Windows 版里就用着，可以做 JSON 编解码。）

## 七、编码约定（求你遵守，不然合并时很痛苦）

| 约定 | 原因 |
|---|---|
| `core/` 里禁止出现 `import android` | 它要能在 JVM 上跑单测 |
| 游戏状态只在渲染线程改 | 主线程改了会和渲染线程打架（`ConcurrentModificationException`） |
| 网络 IO 不放在渲染线程 | 会卡画面、会 ANR |
| 图片放 `res/drawable-nodpi`，文件名全小写 | 大写会导致 R 不生成；nodpi 防止被密度放大 |
| 坐标按逻辑宽度 512 算，别写死像素 | 换屏幕就错位 |
| 新资源记得 `Clean Project` 再 Rebuild | R 文件不会自动刷新 |

## 九、卡住了怎么办

| 现象 | 先看哪里 |
|---|---|
| R 找不到 / 编译报 Cannot resolve symbol R | 查 res 目录有没有大写文件名；然后 Build → Clean Project → Rebuild |
| 测试报 ClassNotFoundException 但 class 存在 | 你的项目路径是不是有中文？ |
| 装不上 APK | 手机纯净模式？签名冲突？先 `adb uninstall edu.hitsz.aircraftwar` |
| 游戏黑屏 | logcat 搜 `资源解码失败` |
| 想验证不改坏核心逻辑 | 跑 `testDebugUnitTest`，22 项要全绿 |

有拿不准的，把 logcat 的堆栈贴出来问，别只说"运行不了"。
