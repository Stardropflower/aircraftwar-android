## 一、先用一句话说清这个项目

> 这是一个「飞机大战」游戏，我把原来 Windows 版（Java Swing）的游戏规则原封不动搬到安卓上，
> 只替换了"画图、听声音、收触摸"这几件和平台绑定的事。

记住这句话，验收时很多问题都能绕着它回答。

---

## 二、整个项目就三层，像一台机器

```
┌────────────────────────────────────────────────┐
│  ui/        界面层（含 ui/visual 自绘菜单动画）   │ 11 个文件
│  render/    渲染层 —— 画图、主循环、触屏          │  3 个文件
│  audio/     音频 —— SoundPool / MediaPlayer     │  1 个文件
│  data/ db/  存储 —— SharedPreferences / SQLite  │  4 个文件
│  net/       网络对战（实验五，本次验收不含）      │  4 个文件
├────────────────────────────────────────────────┤
│  core/      核心层 —— 游戏规则，纯 Java，零安卓依赖│ 43 个文件
└────────────────────────────────────────────────┘
```

用个更好记的比方：

| 层 | 打比方 | 负责什么 | 关键约束 |
|----|--------|----------|----------|
| `core/` | **发动机** | 敌人怎么飞、子弹怎么打、碰撞怎么算、谁得分、什么时候死 | **一行安卓代码都没有** |
| `render/` | **仪表盘 + 油门** | 把发动机的状态画到屏幕上、每 40 毫秒踩一次"油门"让发动机转一步、把手指位置告诉发动机 | 依赖安卓，但**不含游戏规则** |
| `ui/` | **车钥匙和外壳** | 页面跳转、全屏设置、退回桌面时暂停 | 越薄越好 |
| `ui/visual/` | **仪表盘的装饰件** | 主菜单的星空背景、开场动画、二级弹出面板、皮肤预览 | 纯自绘、不碰游戏状态 |
| `net/` | **对讲机**（实验五） | 房间、比分上报、断线重连 | 本次验收不涉及 |

### 为什么非要这么分？这是最重要的一点

因为**发动机不插电也能单独测**。

`core/` 里没有任何 `import android.*`。带来的好处：

1. 它能在**普通电脑上跑单元测试**（不用模拟器、不用手机），所以我有 22 项测试全绿；
2. 同一份 `core/` 理论上 Windows 版和安卓版**可以共用**；
3. 换平台时（以后要是做小游戏平台），只需要重写 `render/`。

老师如果问"你为什么要分层""分层有什么好处"，**上面这三条就是标准答案**。

怎么证明它真的没依赖安卓？跟老师说：
> "core 包里搜不到一个 `import android`，而且 `app/src/test` 里的测试是纯 JVM 跑的，没启动模拟器。"

## 三、建议的阅读顺序（40 分钟）

**不要从第一个文件开始挨个读**，会迷路。按下面这个顺序，每一步都建立在前一步上：

### 第 1 步（10 分钟）：先看游戏的"心跳"

📄 `core/GameWorld.java` 的 **`update()`** 方法

这是全项目最重要的一个方法。它每 40 毫秒被调用一次，一次就推进游戏的一小步。
方法体只有十几行，按顺序干了这些事：

```java
public void update() {
    snapshotPositions();      // ① 记下所有东西现在在哪（为了画面平滑，后面讲）
    updateBoosts();           // ② 火力加速倒计时 -1
    updateFreezeFrames();     // ③ 冰冻剩余时间 -1
    checkBossSpawn();         // ④ 分数够了就放 Boss
    spawnEnemies();           // ⑤ 按节奏刷敌机
    shootAction();            // ⑥ 谁该开火谁开火
    bulletsMoveAction();      // ⑦ 所有子弹往前飞
    aircraftMoveAction();     // ⑧ 所有敌机往前飞
    itemsMoveAction();        // ⑨ 所有道具往下飘
    crashCheckAction();       // ⑩ 检查碰撞：谁撞了谁
    postProcessAction();      // ⑪ 把死掉的东西从列表里删掉、处理掉落
    scrollBackground();       // ⑫ 背景往下滚一格

    if (isAnyHeroDead()) finishGame();   // ⑬ 玩家死了就结束
    else progressionStep();              // ⑭ 否则看看该不该提高难度
}
```

**这 14 步就是整个游戏的完整逻辑。** 你能把这 14 步讲出来，验收就过了一大半。

> 💡 老师可能问："为什么碰撞检测要放在移动之后？"
> 答："因为要先算出这一帧所有人飞到哪里，再判断有没有撞上。如果先判碰撞再移动，
> 那判定用的是上一帧的位置，会出现子弹穿过敌机的情况。"

---

### 第 2 步（8 分钟）：所有东西的"老祖宗"

📄 `core/basic/AbstractFlyingObject.java`

游戏里飞的每一样东西——敌机、子弹、道具、你的飞机——都继承它。它只管 4 件事：

1. **位置和速度**（`locationX/Y`、`speedX/Y`）
2. **`forward()`**：按速度往前挪一步
3. **`crash()`**：判断两个东西有没有重叠（碰撞）
4. **`vanish()` / `notValid()`**：标记"我死了"，但**不立刻从列表里删除**（统一在第 ⑪ 步清理）

> 💡 为什么"死了"不马上删？
> 答："因为碰撞检测正在遍历列表，边遍历边删会抛 `ConcurrentModificationException`。
> 所以先打个'已失效'的标记，等这一帧所有判定都做完了，再统一清理。"

这是**并发编程里很常见的手法**，讲出来能加分。

里面有个容易看漏的细节：`crash()` 里的 `factor`。

```java
int factor = this instanceof AbstractAircraft ? 2 : 1;
```

意思是：**飞机的判定框高度只算一半**，子弹和道具算全部。
所以飞机的碰撞框比它看起来要"扁"——这是原版刻意调的手感，让玩家更容易躲子弹。
如果你的飞机明明没碰到敌机却死了，或者明明看着撞上了却没死，就是被这个影响。

---

### 第 3 步（8 分钟）：你的飞机

📄 `core/aircraft/HeroAircraft.java`

看这几个地方：

| 看什么 | 在哪 | 为什么重要 |
|--------|------|-----------|
| 满血 1000、初始火力 30 | 开头的常量 | 数值问题 |
| `shoot()` | 方法 | 它自己不干活，交给**射击策略**（下一节） |
| `setFireBoost()` / `tickBoost()` | 方法 | 吃到火力道具后 6 秒的效果 |
| `Skin` 枚举 | 内部枚举 | 七款皮肤和它们的解锁条件 |
| `resetAt()` | 方法 | 重新开始一局时把状态清干净 |

**这里有个和 Windows 版不一样的设计，老师可能会问**：

原版用「后台线程 + `SwingUtilities.invokeLater`」来实现火力加速到期。
安卓上没有 `SwingUtilities`，我改成了**按帧数倒计时**：

```java
public static final int BOOST_DURATION_FRAMES = 150;   // 150 帧 × 40ms = 6 秒
```

好处：① 不依赖平台；② 是确定性的（同样的帧数，不管手机快慢都是 6 秒）；
③ 可以在单元测试里直接验证。

> 💡 老师问："为什么不用 Handler 定时？"
> 答："用帧数更确定，而且不引入第二个时间源。游戏本来就是按帧推进的，
> 用帧数计时和其他逻辑是同一个时钟，测试也好写。"

---

### 第 4 步（8 分钟）：射击为什么能换来换去

📄 `core/strategy/` 整个文件夹（6 个文件，都很短）

这是**策略模式**。一句话：

> 飞机只管"我要开火"，具体打出几发、什么角度，由"策略"决定，策略可以随时换。

| 文件 | 干什么 | 什么时候用 |
|------|--------|-----------|
| `ShootStrategy` | 接口，只有一个 `shoot()` | —— |
| `StraightShootStrategy` | 竖直平行打 | 默认 |
| `SpreadShootStrategy` | 扇形散开 | 吃到火力 / 玩家切换 |
| `RoundShootStrategy` | 一圈 20 发 | 超级火力、Boss 弹幕 |
| `EliteProShootStrategy` | 三向散弹 / 四连发交替 | 精英 Pro 敌机 |
| `ShootContext` | 拿着当前策略，负责调用 | 飞机持有它 |

> 💡 老师问："这里为什么用策略模式，用 if-else 不行吗？"
> 答："可以，但用策略的话，加一种新弹幕只需要新建一个类，不用改动飞机和现有的策略；
> 而且玩家的子弹和 Boss 的弹幕能共用同一套切换机制。"

---

### 第 5 步（6 分钟）：怎么画、谁在驱动

📄 `render/GameRenderer.java` 和 `render/GameSurfaceView.java`

**`GameRenderer`**：只管画。它不修改任何游戏数据。

关键点是**坐标缩放**：游戏内部永远按"逻辑宽度 512"计算，画的时候统一放大到屏幕尺寸。
这样游戏数值和手机分辨率彻底解耦——换个屏幕不用改任何游戏参数。

**`GameSurfaceView`**：这是整个安卓版的"发动机皮带"。它开了一个**专门的线程**，每轮做三件事：

```
1. 现在离上次推进够 40ms 了吗？够 → 调 world.update() 推进一步
2. 算出"离上一步过去了百分之多少"（这个百分比叫 alpha）
3. 拿 alpha 去画一帧
```

> 💡 老师问："为什么游戏循环要放独立线程，不能放主线程？"
> 答："安卓主线程还要处理触摸、页面切换这些事，时间不可控。
> 而且主线程一旦被阻塞超过 5 秒就会 ANR（应用无响应）崩溃。
> 游戏循环必须有自己的线程，这是 Android 官方对游戏开发的标准建议。"

> 💡 老师问："你在渲染线程里直接读触摸坐标吗？怎么保证线程安全？"
> 答："没有直接读。触摸事件在主线程，只往 volatile 变量里写目标坐标；
> 渲染线程在每个逻辑步开头统一取一次应用给飞机。这样游戏状态永远只在渲染线程里被修改。"

## 四、杀手锏：讲一遍「一颗子弹的一生」

如果老师让你"随便挑个功能讲讲流程"，讲这个最稳，因为它能串起整个项目：

1. **玩家手指按在屏幕上**
   → `GameSurfaceView.onTouchEvent()` 记下坐标（主线程）

2. **渲染线程下一个逻辑步开始**
   → `applyInput()` 把英雄机挪到手指位置（往上偏 70 个逻辑单位，免得手指挡住飞机）

3. **计帧数**：`shootAction()` 里数到第 10 帧（普通模式）
   → 调用 `hero.shoot()`

4. **英雄机把活甩给策略**：`HeroAircraft.shoot()` → `ShootContext.executeShoot()`
   → `StraightShootStrategy.shoot()` 造出 2 颗 `HeroBullet`，速度 -20（向上）

5. **给子弹盖上"主人戳"**：`bullet.setOwnerIndex(i)`
   —— 这一步是为了双人模式下算分算对人

6. **每帧往前飞**：`bulletsMoveAction()` → `BaseBullet.forward()`，y 减 20；飞出屏幕就 `vanish()`

7. **检查碰撞**：`crashCheckAction()` 拿这颗子弹和每个敌机做矩形重叠判断

8. **打中了**：`enemy.decreaseHp(子弹威力)`，然后**子弹立刻 `vanish()`**

9. **敌机血空了**：`enemy.vanish()` 标记失效，分数加给 `bullet.getOwnerIndex()` 那个玩家

10. **这一帧结束时统一清理**：`postProcessAction()` 把失效的敌机从列表删掉，
    并检查它该不该掉道具（`dropCount()`）

11. **画面更新**：`GameRenderer` 用插值坐标把所有还活着的东西画出来

> 讲这个流程的时候，顺手就能带出三个设计点：
> **策略模式**（第 4 步）、**观察者/回调**（第 9 步的计分）、**延迟清理**（第 10 步）。

## 五、五个最核心的设计决策（老师最爱问"为什么"）

| # | 决策 | 大白话解释 | 不说会怎样 |
|---|------|-----------|-----------|
| 1 | **核心层零安卓依赖** | 发动机不插电也能测 | 每测一次都要开模拟器，改一行等 5 分钟 |
| 2 | **逻辑 25Hz、渲染 60fps，两者分离** | 游戏规则每 40ms 算一次，但画面每秒画 60 次，中间用插值补 | 画面会一格一格跳，像幻灯片 |
| 3 | **死了不马上删，先打标记** | 边遍历边删列表会崩 | `ConcurrentModificationException` |
| 4 | **坐标全部按逻辑宽度 512 算，画的时候再放大** | 游戏数值不认识屏幕分辨率 | 换个手机游戏就变形或错位 |
| 5 | **射击方式用策略模式** | 开火方式是可插拔的零件 | 一堆 if-else，加一种弹幕要改好几处 |
| 6 | **贴图分辨率与碰撞框解耦** | 图可以换高清，碰撞框钉死在逻辑尺寸 | 换一次高清贴图，碰撞框跟着放大 N 倍，游戏直接没法玩 |

### 第 2 条值得单独讲，因为它最容易被追问

**问题**：为什么不干脆让逻辑也跑 60Hz？

**答**：因为**逻辑步长一改，整个游戏的数值就全变了**。
所有速度都是"每帧移动多少像素"：敌机 `speedY = 10` 意思是每帧下降 10 像素。
如果逻辑从 40ms 改成 16ms，敌机速度就变成原来的 2.5 倍，游戏直接没法玩。

所以正确做法是：**逻辑保持 25Hz 不动，把渲染提高**，中间用插值：

```
第 N 步（位置 100）        第 N+1 步（位置 110）
     |----------- 40ms -----------|
     ↑ 在这 40ms 里，画面依次画在 100、102、104…110
       而不是"卡"在 100 然后突然跳到 110
```

插值系数 `alpha` 就是"离上一次推进过去了百分之几"。
画的时候位置 = 上一帧位置 + (当前帧位置 - 上一帧位置) × alpha。

### 第 6 条也值得单独讲，因为它是最近改贴图时才暴露出来的

**问题**：贴图从 100×83 换成了 300×249（正好 3 倍高清），为什么游戏没变难？

**答**：因为我们把**贴图分辨率**和**碰撞框尺寸**拆开了：

- `Assets.logicalAircraftBox()` 把六种飞机的逻辑宽高**钉死在换图之前的数字**（英雄机 100×83、Boss 300×200……）
- `GameRenderer.drawEntities()` 改成按 `object.getWidth()/getHeight()` 把 3 倍图**缩放绘制**回逻辑尺寸

如果偷懒直接用位图像素当碰撞框，换完高清贴图后英雄机的判定范围会变成 3 倍，
看着没碰上的敌机也会撞死——**这类"只改了美术"的改动，最容易把玩法悄悄改坏**。

> 我在 Windows 版上实测过：一开始图省事，让渲染节拍去对齐逻辑基准，
> 结果实际步长被撑到 48ms，等于游戏整体慢了 20%。这个问题后面专门讲过。

## 六、和 Windows 版比，我到底改了什么

**游戏规则一行没改**（Boss 阈值、炸弹 100 伤害、冻结 150 帧、背包容量 2、掉率……全部照搬）。
改的只有这些：

| 原来（Windows） | 现在（安卓） | 为什么必须改 |
|---|---|---|
| `JPanel.paintComponent` + `Graphics2D` | `SurfaceView` + `Canvas` | 安卓没有 Swing |
| `javax.swing.Timer` | 独立线程 + 时间累加器 | 安卓主线程不能跑游戏循环 |
| `MouseListener` / `KeyListener` | `onTouchEvent` | 手机没有鼠标键盘 |
| `BufferedImage` 存在实体里 | 实体只存宽高，图片归渲染层 | 让核心层不依赖图像类型 |
| 英雄机 `getInstance()` 单例 | 可以 new 多个 | 双人合作需要两架飞机 |
| 敌机死后自己调 `Game.getInstance()` 塞道具 | 由 `GameWorld` 统一处理 | 实体不该反向依赖 UI 类 |
| `javax.sound.sampled.Clip` | **还没做** | 安卓没有 Java Sound |

其中第 4、5、6 条是**结构上的改进**，不只是换个写法：
- 第 4 条让核心层能单测
- 第 5 条让双人成为可能
- 第 6 条去掉了"实体 → UI"的反向依赖

> 这些是**能主动讲出来的加分点**：说明你不是机械地复制代码，而是理解了设计意图。

## 七、代码里容易踩的坑（可能被问到细节）

| 坑 | 在哪 | 说明 |
|---|------|------|
| 子弹不穿透 | `GameWorld.crashCheckAction()` 里 `if (bullet.notValid()) break;` | 一颗子弹打完一个敌人就消失。这是 Windows 版修过的 bug，安卓版沿用正确版本 |
| 撞机判定独立于子弹 | `crashCheckAction()` 第 3 段循环 | 原来这段写在子弹循环里面，玩家没在射击时敌机撞上来不算数——是个 bug |
| 炸弹对 Boss 是**固定伤害**不是秒杀 | `AbstractEnemy.dropCount()` / `onBombDetonated()` | 杂兵全灭，Boss 和精英 Pro 各扣 100 |
| 被炸弹炸死的不掉道具 | `AbstractEnemy.dropCount()` 第一行 | `killedByBomb` 检查 |
| 背包是**栈**，后进先出 | `GameWorld.useBackpackItem()` | 按空格/按钮用的是**最后捡到**的那个，界面高亮也要跟着这个 |
| 掉落概率是**击杀时**才随机的 | `shouldDropItem()` | 不是刷出来时决定的 |
